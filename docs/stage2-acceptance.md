## 三套策略已接入正式逐期流程

官方資料同步 → 結算原封存及影子預測 → 原子更新模型／三策略成績、監控與控制器 → 診斷 → 選擇未來候選視窗 → 產生下一期 → 同交易封存正式及三套研究預測。所有策略各有三星、四星、五星的選號、完整分數、特徵／訓練截止期、實際歷史範圍、模型／政策版本與決策雜湊；同一期不可覆寫。過期期間只補官方答案，不補造預測。

Today Only 的模型與增量狀態按目標台北日期隔離，工件 manifest 另驗證來源日期。少於 10 期採明示先驗；模型未就緒時只使用當天真正的頻率／CDM。當資料成熟才排程訓練適用模型，與歷史模型共用受限背景工作佇列。Historical 保留跨日基準；Hybrid 只用已結算的過去配對實績調整當日權重。前三十期等權，之後保守收縮，不假設每日存在可利用模式。

三套實戰共同榜獨立於原模型實戰榜，歷史模擬完全分開。至少 300 共同期數及 3 日後才定期檢查，採重複比較校正、平均命中改善及全中率非劣門檻、100 期冷卻；未通過維持 Historical。這是最早可比較門檻，並非 300 期後一定切換。

## 已知界線

- 開發期間只能取得短時間真實事前樣本，尚未完成數百期多日實戰；程式已持續封存並有切換保護，不能以歷史重播代替數日後才能得到的結果。
- 真實歷史比較尚未證明策略優於隨機，也未證明 Today Only 比跨日資料更準；切換門檻刻意保守，可能長期不切換。
- Today 與 Historical 的可用樣本、模型成熟程度及訓練頻率不同，結果是各自部署流程的比較，不能單獨證明「每天模式不同」。更長期、預先指定日期的對照仍有必要。
- 視窗主要改變推論上下文；重型模型批次訓練範圍另列。只有通過獨立參數驗證才變更批次訓練工件，不能把特徵視窗縮短宣稱為重新訓練。
- 巢狀及三套模型增加訓練／稽核記憶體；每輪候選與 CPU 受限，並非零額外成本。長期不可覆寫封存及每日模型版本會累積磁碟用量，需由部署端依保留需求備份／歸檔；本次不刪除任何既有正式紀錄或工件。
- 官方 API 發布延遲與時間 sentinel 限制沿用第一階段紀錄，45 秒輪詢不能消除上游延遲。沒有數週運行、多人高併發、主機斷電或正式部署 SLA 的實測宣稱。
- 驗證使用隔離本機資料庫及副本，沒有修改使用者已發佈環境。合併後仍需既有部署流程執行 Alembic 新增遷移及啟動單一主程序。
